# Передать DS v2 в код

Загрузить навык `one-flow-ds`. Значения не придумывать.

## Шаг 0 — готовый кит
Сначала отдать то, что уже снято с Figma и сверено: `assets/tokens.css` + `assets/typography.css` (все токены и 4 режима темы), `assets/components.css` (все компоненты `.of-*`), `assets/icons.svg`, `assets/logo/`, спецификации `references/components/*.md`. Как собрать экран — `references/code-screen.md`. Для этого доступ к Figma не нужен.
Figma читать, только если нужно то, чего в ките нет (новый компонент, свежая правка в библиотеке), или сверить значение.

## Что бывает нужно

### Токены в CSS
0. Есть готовые: `assets/tokens.css` (имена — ниже). Если в проекте свои имена — сделать таблицу соответствия к ним, значения не копировать руками. Шаги 1–6 — когда токены нужно снять заново.
1. Прочитать переменные: `get_variable_defs` по узлу или `use_figma` в файле библиотеки (`figma.variables.getLocalVariableCollectionsAsync`, значения по режимам).
2. Имена: путь Figma → CSS, `/` → `-`: `surface/brand/brand` → `--surface-brand-brand`, `space/16` → `--space-16`, `radius/xl` → `--radius-xl`, `brand/600` → `--brand-600`. Если в проекте уже есть свои имена — спросить и сделать таблицу соответствия.
3. Режимы: `colors` Light — `:root`, Dark — `[data-theme="dark"]` и `@media (prefers-color-scheme: dark)`, контрастные — `[data-contrast="more"]`. Бренд клиента — `[data-brand="<клиент>"]` переопределяет только `--brand-*`; роли ссылаются на них через `var()`, а не копируют HEX.
4. Ссылки между переменными сохранять ссылками (`--surface-brand-brand: var(--brand-600)`), сырые HEX — только в шкалах (`palette`, `brand`).
5. Шрифты: Onest, JetBrains Mono; стили — набор классов или переменных `font` по таблице `foundations.md`.
6. Движение: `--duration-*`, `--easing-*` + обязательный блок `@media (prefers-reduced-motion: reduce)`.

### Спецификация компонента
0. Сначала `references/components/<страница>.md` и блок компонента в `assets/components.css` — там анатомия, токены по состояниям, правила доски, разметка и расхождения.
1. Если нужно свежее или подробнее — найти компонент (`search_design_system`), прочитать описание и Specs на его странице (`rules-index.md`), `get_design_context` по варианту.
2. Отдать: назначение; свойства и варианты (как props); размеры, отступы, радиусы — именами токенов; состояния (hover, focus, disabled, loading, error) и что в них меняется; поведение и движение (токены длительности и кривой); доступность (роль, клавиатура, фокус, aria-подписи, мин. зона нажатия 24 px веб / 44 px мобильный); тексты на языке продукта; правила использования с доски.
3. Формат по запросу: markdown-спецификация, интерфейс props (TypeScript), или код компонента в стеке пользователя. Стек не угадывать — спросить или посмотреть в проекте.

### Экран
Свёрстанный экран — по `references/code-screen.md` из кита. Экран из макета: `get_design_context` по фрейму → сопоставить слои с компонентами DS (по имени главного компонента) → перечислить, какие компоненты и токены используются, и где в макете есть отступления от DS (прогнать `scripts/lint.js`).

## Правила
- Не вставлять HEX там, где есть роль.
- Не выдумывать значения: если токена нет — сказать и предложить ближайший.
- Тёмная тема и бренд клиента обязательны с первого дня — роли, а не цвета.
