# Проверить макет по DS v2

Загрузить навык `one-flow-ds`. Ничего в файле не менять, пока пользователь не попросит исправить.

## Шаги

1. Получить ссылку на фрейм (fileKey и node-id). Нет — попросить.
2. `get_screenshot` фрейма — посмотреть целиком.
3. Запустить `scripts/lint.js` навыка `one-flow-ds` через `use_figma` с `TARGET` = id фрейма.
4. Тёмную тему проверять на временной копии фрейма, только если пользователь разрешил её создать (и удалить копию после). Без разрешения — указать тёмную тему как непроверенную.
5. Проверить глазами то, что скрипт не умеет:
   - правильный ли компонент выбран для задачи (по `patterns.md` и доскам правил);
   - одна главная кнопка на блок, порядок кнопок, тексты (`writing.md`);
   - статусы — иконка или точка + слово; Spark только как метка;
   - графики — ряды синими, подписан период и источник;
   - контраст текста (4.5:1, крупный 3:1) на подозрительных местах;
   - сетка: контент 1104, лента 784 + колонка 304, каркас страницы;
   - нет ли выдуманных «реальных» данных и неизвестных фактов без `[X]`.

## Ответ

Сначала вердикт одной фразой. Затем список, сгруппированный по важности:
- **Ломает систему** — HEX вместо токенов, отвязанные компоненты, чужие шрифты и стили, нарушения главных правил.
- **Стоит исправить** — радиусы и отступы вне шкалы, эффекты без стиля, неудачный выбор компонента, тексты.
- **К сведению.**

Для каждого пункта: где (имя слоя и ссылка на узел), что не так, как исправить (какой компонент, токен или стиль поставить). Одинаковые замечания объединять («14 слоёв с HEX-заливкой: …»). В конце — предложить исправить автоматически то, что можно (токены, стили), и спросить, делать ли.
